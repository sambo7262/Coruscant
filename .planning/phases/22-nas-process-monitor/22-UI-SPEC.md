## Component Inventory

### NasProcessPanel (new component)

Structural analog: `WeatherForecastPanel.tsx` + `DockerUpdatePanel.tsx`

```
NasProcessPanel
  motion.div.nas-process-panel          ← AnimatePresence slide-down, same as WeatherForecastPanel
    div.nas-process-panel__inner          ← padding: 10px 16px
      div.nas-process-panel__header       ← "NAS LOAD — CPU {N}%"
      [loading state]                     ← amber pulse skeleton
      [error state]                       ← error message row
      [process rows × 5 max]
        div.nas-process-panel__row
          span.nas-process-panel__label   ← human-readable name (or raw fallback)
          div.nas-process-panel__bar-wrap
            div.nas-process-panel__track  ← 16px height, rgba(232,160,32,0.15) bg
            div.nas-process-panel__fill   ← width: {cpu}%, color varies by load level
          span.nas-process-panel__pct     ← "{N}%"
```

### NAS tile CPU tap affordance (modification to existing ServiceCard / NAS tile area)

When `cpu > 30%`: render a tappable wrapper around the CPU metric row with:
- `cursor: pointer` (kiosk/desktop)
- `touch-action: manipulation` (iPhone)
- `-webkit-tap-highlight-color: transparent`
- A `▾` chevron (10px, `rgba(232, 160, 32, 0.6)`) appended after the CPU% value
- `min-height: 44px` on iPhone viewports (RESP-08 touch target)
- Pattern: button `all: unset` reset — matches `.nas-tile__docker-update-btn`

When `cpu <= 30%`: CPU metric row renders as plain text, no tap target, no chevron.

## Interaction Contract

### Panel open/close

- Tap CPU metric on NAS tile (when elevated) → opens NasProcessPanel
- Tap anywhere outside panel (backdrop) → closes panel
- Tap CPU metric again while panel open → closes panel
- Panel state: `processMonitorOpen` boolean in AppHeader (or ServiceCard + prop callback) — follows same mutual-exclusion pattern as `forecastOpen` / `panelOpen`
- Only one panel open at a time — opening NasProcessPanel closes forecast and docker-update panels

### On-demand fetch

- Fetch fires when panel opens (not before)
- Endpoint: `GET /api/nas/processes`
- Loading state: amber pulse on panel body (`.sparkline-loading` pattern — `arrDownloadPulse` animation)
- Success: render process rows
- Error: show error copy row (see Copywriting)
- Stale: no stale concept — each panel open triggers a fresh fetch; data is not cached between opens

### Memory/process display (D-12 discretion)

- Show CPU % only, not memory. Memory alongside CPU % would crowd the narrow row format; CPU is the primary concern. Memory can be added in a future phase.
- Show top 5 processes sorted by CPU % descending (D-06)

### Bar animation

- Width transition: `0.6s ease` (matches `.nas-tile__metric-fill` transition)
- On panel open, bars animate from 0% to actual value — entrance motion only, no continuous animation

## States

| State | Trigger | Visual Treatment |
|-------|---------|-----------------|
| No affordance | CPU ≤ 30% | CPU metric is plain text; no chevron; no tap target |
| Affordance visible | CPU > 30% | Chevron `▾` appended; CPU row is tappable |
| Panel loading | User taps; fetch in flight | Panel open, header shows "NAS LOAD — CPU {N}%", body shows amber pulse skeleton (height ~70px) |
| Panel populated | Fetch succeeds | Process rows render with bar entrance animation |
| Panel empty | Fetch returns 0 processes | "NO PROCESS DATA" in green (matches panel empty pattern) |
| Panel error | Fetch fails (DSM unreachable) | Error row in red: "DSM UNREACHABLE — CHECK NAS CONNECTION" |
| Panel stale | N/A | Not applicable — always fresh on open |

## Responsive Overrides (viewport-iphone.css)

iPhone portrait and landscape must include:

```css
/* nas-process-panel safe-area top offset — mirrors weather-forecast-panel */
html[data-viewport^="iphone"] .nas-process-panel {
  top: calc(44px + env(safe-area-inset-top));
}

/* CPU tap affordance touch target */
html[data-viewport^="iphone"] .nas-tile__cpu-tap-btn {
  min-height: 44px;
  touch-action: manipulation;
  -webkit-tap-highlight-color: transparent;
}
```

Process rows maintain readable sizing at iPhone scale. No font or layout overrides needed — 10px/12px values in this panel are already readable at arm's length on Retina displays (project precedent: DockerUpdatePanel uses same sizes on iPhone without override).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None — read-only monitor, no user action beyond tap-to-open |
| Panel header | "NAS LOAD — CPU {N}%" (e.g. "NAS LOAD — CPU 73%") |

| Loading state | No text — amber pulse skeleton (visual only) |

Copy style rules (project standard):
- ALL CAPS throughout
- No punctuation except em-dash separator (` — `)
- Monospace font at all sizes
- Amber for headers/labels; off-white for values; green for positive confirmations; red for errors
