## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|

## Component Contract

### WeatherForecastPanel

The forecast panel is a new component following DockerUpdatePanel's exact structural pattern.

**Container:** `position: fixed; top: 44px; left: 0; right: 0; z-index: 9` — same stacking and positioning as `.docker-update-panel` and `.pi-health`. This places it immediately below the AppHeader.

**Background:** `rgba(13, 13, 13, 0.97)` — identical to docker-update-panel and pi-health panels.

**Bottom border:** `1px solid rgba(232, 160, 32, 0.25)` — identical to docker-update-panel and pi-health panels.

**Animation:** Framer Motion `AnimatePresence` wrapping a `motion.div` with `initial={{ height: 0, opacity: 0 }}`, `animate={{ height: 'auto', opacity: 1 }}`, `exit={{ height: 0, opacity: 0 }}`, `transition={{ duration: 0.25, ease: 'easeInOut' }}` — identical to DockerUpdatePanel. Source: CONTEXT.md D-05.

**Inner padding:** `10px 16px` — matching docker-update-panel__inner.

**Day column layout:** 5 equally-spaced columns in a flex row. `display: flex; justify-content: space-between; align-items: flex-start`. No horizontal scroll on kiosk or landscape. On iphone-portrait: compress column content (smaller icon + text) to fit — see Responsive section below.

**Each day column contains (top to bottom):**
1. Day name label — "TODAY" for index 0 (CONTEXT.md D-12 — Claude's discretion: use "TODAY" for first entry), "MON" through "SUN" for remaining days. Uppercase, `--text-label` (12px), amber-60%.
2. WeatherIcon — reuse existing component. Size: 24px on kiosk and landscape; 20px on iphone-portrait (CONTEXT.md D-07 — Claude's discretion: 24px fits 5 columns at kiosk 800px width with 16px side padding).
3. High temperature — `var(--tile-font-value)` amber bold. Format: `72°` (no space before degree symbol).
4. Low temperature — `--text-label` (12px) offwhite-50%. Format: `58°`.
5. Condition label — `--text-label` (12px) offwhite. Format: `"Partly Cloudy"`. WMO code mapping: 0 = "Clear", 1 = "Mostly Clear", 2 = "Partly Cloudy", 3 = "Overcast", 45/48 = "Foggy", 51-67/80-82 = "Rain", 71-77/85-86 = "Snow", 95/96/99 = "Thunderstorm". Default fallback: "Cloudy". Source: CONTEXT.md D-13 — Claude's discretion.

**Tap-to-toggle trigger:** The existing weather widget div in AppHeader (`.app-header__weather`) becomes a button. Tapping toggles `forecastOpen` state. Tapping again, or tapping anywhere outside the panel (backdrop click), closes it. Source: CONTEXT.md D-04. Pattern: identical to `panelOpen` for PiHealthPanel in AppHeader.

**Backdrop:** Semi-transparent backdrop `rgba(0,0,0,0.4)` at `z-index: 8` (one level below panel at z-index 9) — matches now-playing-banner__backdrop pattern. Tapping backdrop dismisses panel. Note: PiHealthPanel does not use a backdrop; DockerUpdatePanel does not use a backdrop. For the forecast panel, use a backdrop to provide a clear dismiss target since the panel overlaps the main content area.

**AppHeader weather widget button wrapper:** Must satisfy `min-height: 44px` touch target on iPhone (already satisfied by `.app-header__weather { height: 44px }`). Add `cursor: pointer` and `touch-action: manipulation` on iphone viewports via viewport-iphone.css.

**Panel section header:** "5-DAY FORECAST" text at `--text-label` (12px) amber-50% letter-spacing 0.08em uppercase — matching docker-update-panel__header pattern, updated to 12px to stay within the 4-size scale.

**Empty/loading state:** If forecast array is empty or undefined, show: "FORECAST UNAVAILABLE" in `--text-label` (12px) `var(--cockpit-green)` — matching docker-update-panel "ALL IMAGES UP TO DATE" pattern (same color used for "all good" states).

**Error state:** If weather fetch has failed, show: "NO FORECAST DATA — CHECK CONNECTION" in `--text-label` (12px) amber-50%.

## Responsive Contract

### Kiosk (800x480, `data-viewport="kiosk"`)
- Panel drops below 44px header, full width
- 5 day columns: `display: flex; justify-content: space-between; padding: 10px 16px`
- WeatherIcon size: 24px per day column
- High temp: 22px (`--tile-font-value`)
- All 5 columns visible without scroll
- Panel total height: approximately 90-100px (icon 24px + text rows ~50px + padding 20px)

### iPhone Portrait (`data-viewport="iphone-portrait"`)
- Panel drops below `calc(44px + env(safe-area-inset-top))`
- Strategy (CONTEXT.md D-11 — Claude's discretion): **column compression with smaller text/icons** rather than horizontal scroll. Rationale: horizontal scroll breaks the cockpit instrument-panel feel; compression keeps all 5 days scannable at once.
- WeatherIcon size: 18px per day column
- High temp: override `--tile-font-value` to 16px via `html[data-viewport="iphone-portrait"]` selector
- Day name: use `--text-label` (12px) — no separate size
- Condition label: use `--text-label` (12px) — may truncate to 8 chars if needed
- Low temp: use `--text-label` (12px) — no separate size
- Panel inner padding: `8px 16px` (8px vertical, 16px horizontal — standard grid values)
- Add these rules under `html[data-viewport="iphone-portrait"]` in `viewport-iphone.css`
- Touch target for weather widget button: already 44px via `.app-header__weather { height: 44px }`

### iPhone Landscape (`data-viewport="iphone-landscape"`)
- Same layout as kiosk but with `env(safe-area-inset-left)` / `env(safe-area-inset-right)` padding to clear Dynamic Island
- WeatherIcon size: 20px per day column
- High temp: 18px
- All other sizes match kiosk

**CSS scoping rule:** All iphone overrides go in `viewport-iphone.css` under the appropriate `html[data-viewport...]` selector. No `!important`, no `@media`. This is enforced by CI lint.

## Interaction Contract

| Interaction | Trigger | Result |
|-------------|---------|--------|
| Open forecast panel | Tap weather widget (icon + temp) in AppHeader | Panel slides down, backdrop appears |
| Close forecast panel | Tap backdrop OR tap weather widget again | Panel slides up, backdrop disappears |
| Stale data indication | `WeatherData.fetched_at` age > 20 minutes | Existing `StaleIndicator` component already shown on weather widget; panel inherits same stale state (dim forecast to opacity 0.5 + show "Last updated Xm ago" sub-label under panel header) |
| Panel + PiHealth panel conflict | Both `panelOpen` (pi health) and `forecastOpen` are independently managed | Opening forecast closes pi-health panel, and vice versa — only one panel open at a time. Enforced via `setPanelOpen(false)` when `setForecastOpen(true)` and vice versa. |

**AnimatePresence wrapping location:** Both panels (`PiHealthPanel` and `WeatherForecastPanel`) are rendered inside `AnimatePresence` blocks in AppHeader's return, just as `PiHealthPanel` currently is. Add a second `AnimatePresence` block for the forecast panel.
